# 指标口径（METRICS）

这份文档是「同一个数字只能有一种算法」的落地清单。报告、SQL、测试三处口径必须一致，
任何一处改动都要同步改另外两处。

## 一、基础指标

| 指标 | 公式 | 说明 |
|---|---|---|
| 曝光量 | `count(impressions)` 或 `SUM(impressions)` | 曝光级日志按行计，聚合报表按列加总 |
| 点击量 | `SUM(clicks)` | 曝光级日志里 click 是 0/1 标记 |
| 转化数 | `SUM(conversions)` | 同上 |
| CTR | 点击 / 曝光 | 素材与定向的吸引力 |
| CVR | 转化 / 点击 | 承接页与转化链路效率 |
| 曝光转化率 | 转化 / 曝光 | 全链路（= CTR × CVR） |
| CPC | 消耗 / 点击 | |
| CPM | 消耗 / 曝光 × 1000 | 流量成本，成本的源头 |
| CPA | 消耗 / 转化 | |
| 归因覆盖率 | 归因转化 / 全部转化 | 回传链路完整性，不是效果指标 |
| 单转化点击数 | 点击 / 转化 | 转化环节顺不顺的相对量度 |

**所有比率一律「先加总再相除」。** 对行级比率求平均会把小样本行同等加权：
`tests/test_aggregate.py::test_ratio_is_sum_then_divide_not_mean_of_ratios` 里构造的
数据，正确 CTR 是 1.49%，而朴素平均得到 25.5%——差 17 倍，报表却看不出异常。

## 二、计费口径换算（CPM / CPC / CPA / oCPC）

投放里最容易说错的一环。四条恒等式：

| 换算 | 公式 |
|---|---|
| CPC → CPM | `CPM = CPC × CTR × 1000` |
| CPM → CPC | `CPC = CPM / (CTR × 1000)` |
| CPC → CPA | `CPA = CPC / CVR` |
| oCPC 出价的媒体侧等价收入 | `eCPM = CTR × CVR × 目标CPA × 1000` |
| 由 eCPM 反推可承受目标 CPA | `目标CPA = eCPM / (CTR × CVR × 1000)` |

由此得到一条**口径自检恒等式**：

```
CPM ≡ CPA × CVR × CTR × 1000
```

它在数学上必然成立，因此它检验的不是数据对错，而是**报表口径有没有被改动过**
（手工改过某列、聚合层级不一致等）。报告第 1 节会打印「实际 CPM / 反推 CPM / 相对偏离」，
偏离不为 0 即提示口径异常。

命令行走一遍：

```bash
python -m adops billing --ctr 0.02 --cpc 0.5 --cvr 0.05 --target-cpa 10
# CPM = CPC × CTR × 1000 = 10.0
# CPC = CPM / (CTR × 1000) = 0.5
# CPA = CPC / CVR = 10.0
# eCPM（媒体侧等价收入） = CTR × CVR × 目标CPA × 1000 = 10.0
```

## 三、结构指标

| 指标 | 定义 | 用途与阈值 |
|---|---|---|
| HHI | 各计划消耗占比的平方和 | 越接近 1 越集中；> 0.25 视为偏集中。**计划数 < 5 时跳过**（n 个均分计划的 HHI 恒为 1/n，1/3 = 0.333 没有信息量） |
| 前 K 占比 | 消耗最高的 K 个计划占比 | 看头部依赖度；前 1 > 40% 触发结构告警 |
| 基尼系数 | 消耗分布不均衡度 | 比 HHI 更敏感于长尾 |
| 变异系数 | 标准差 / 均值 | 指标在维度上的波动 |
| 标准分 z | (值 − 均值) / 标准差 | 单日消耗节奏异常（\|z\| ≥ 2） |
| 相对变化 | (现期 − 基期) / 基期 | 趋势类诊断 |

## 四、统计口径

全部用标准库实现（`adops/experiment/tests_stats.py`），公式写在代码里，可逐行复核。

### 4.1 两比例检验

- **假设检验**用**合并方差**（原假设：两组同率）：`SE = sqrt(p̄(1−p̄)(1/n₁ + 1/n₂))`
- **置信区间**用**非合并方差**（对真实差异做区间估计），双侧区间
- 混用会让区间偏窄、结论偏乐观，这是常见错误，所以代码里两者分开写

### 4.2 Wilson 区间

CTR 常在 1% 以下，正态近似区间会算出负数下界（报表里出现负 CTR 区间会被直接质疑）。
比例类指标统一用 Wilson 区间，下界天然 ≥ 0。

### 4.3 样本量 / 功效 / MDE

```
n（每组） = (z_{1−α/2} + z_β)² × [p₁(1−p₁) + p₂(1−p₂)] / (p₁ − p₂)²
```

`mde_for_sample` 用二分法反解 MDE（`power_for_effect` 关于 MDE 单调递增），
因此 `样本量公式 → 反查功效 ≈ 目标功效` 可以互相校验（有测试钉住）。

### 4.4 序贯检验（多次查看）

「边跑边看」是投放优化里最常见的方法论错误：每次看都按 0.05 判定，
看 5 次实际假阳性接近 14%。本项目用 **O'Brien-Fleming 消耗函数**控制总 α：

```
第 k 次查看（共 K 次）的名义 α_k = 2 × (1 − Φ( z_{α/2} / sqrt(k / K) ))
```

早期查看的边界极严（第 1 次约 1.2e-5），末期回到名义水平。`--looks` 参数控制查看次数。

### 4.5 多重比较

时段机会（24 个小时）用 **Bonferroni 校正**：`α' = α / 时段数`。
不校正的话，24 次比较里必然有几个「显著」——那是噪声，不是机会。

### 4.6 样本量门槛（先于一切统计）

每条规则的判定都有最小样本量（默认：曝光 1 000 / 点击 30 / 转化 10）。
`--config` 可调，阈值集中在 `configs/default.yaml`。
理由很直接：**小样本下的比率差是噪声，误报的代价是运营对报表失去信任。**

## 五、口径与数据边界的对应关系

| 输入形态 | 处理方式 |
|---|---|
| 曝光级日志（每行一次曝光） | 曝光量 = 行数；click / conversion 作为 0/1 计数 |
| 聚合报表（每行含曝光量/点击量） | 直接取列值，不做行计数 |
| 绝对时间戳（秒） | 转成日历日期（UTC） |
| 相对秒数（公开数据集常见） | 还原为「第 N 天 + 小时」（`D001` 形式），**不伪造日历日期**，报告标注 `relative_day` |
| 消耗字段非货币（如公开数据集） | 报告里标为「口径单位」，只用相对关系比较 |
